# Yardi Canada

> Yardi Canada Ltd. is the Canadian subsidiary of Yardi Systems (Goleta, California) — Toronto HQ, offices in Saskatoon and Vancouver, roughly 500 staff — selling and supporting the Yardi property and investment management stack in Canada: Voyager, Breeze Premier, RentCafe, Home IQ, Matrix and Pulse. It is a system of record for landlords and asset managers, not a listing portal and not a land registry. Its API posture is licensed-access-only: there is no public developer portal and no published REST contract. What IS public, and what changes the picture, is an official MCP server — the Yardi Virtuoso Connector — plus a region-sliced status API that exposes Canadian service health anonymously.

Generated by API Evangelist on 2026-07-26 from apis.yml and the artifacts in this
repository. Yardi serves no llms.txt of its own — notably, https://www.yardi.com/robots.txt

## Start here

- [Become an interface partner](https://www.yardi.com/company/become-an-interface-partner/): the access gate. Apply, sign a Data Exchange Agreement per interface type, develop, beta-test with a pilot client, release. Standard Interface partners must be at least two years old with three or more active Voyager clients; there is an annual per-interface fee.
- [Standard interface options](https://www.yardi.com/services/interfaces/standard-interface-options/): the twelve documented Voyager interface families — Collections, Commercial, Construction, ILS & Guest Card, Maintenance, Master Data, Payables, Receivables, Renters Insurance, Revenue, Screening, Senior Living EHR/eMAR — with 450+ interface partners. MITS and OSCRE lineage claimed; no endpoints, WSDL or schema published.
- [RentCafe API Terms of Use](https://resources.yardi.com/legal/rc-api-tou/): the most machine-adjacent public artifact Yardi serves. Its Schedule A names operations (getapartmentavailability, getfloorplans, getunitpricingdetails, getpropertydetails, getamenities, getofficehours, createlead, getavailableslots, createappointment) and it appears in a legal document rather than in documentation.

## Agent surface (this is the real one)

- [Yardi Virtuoso Connector](https://claude.com/connectors/yardi-virtuoso): official first-party MCP server at https://mcp.virtuoso.ai. Read & Write. Published capabilities: portfolio performance, financial data and NOI comparison, work order management, invoice review and approval, quarterly business review, budget forecasting. Requires a licensed Virtuoso Enterprise tenancy; data access follows existing Yardi user permissions.
- [OAuth protected-resource metadata](https://mcp.virtuoso.ai/.well-known/oauth-protected-resource): RFC 9728, anonymous. Scopes openid, profile, email, offline_access.
- [OAuth authorization-server metadata](https://mcp.virtuoso.ai/.well-known/oauth-authorization-server): RFC 8414, anonymous. Authorization code + PKCE S256 + dynamic client registration.
- tools/list is NOT anonymously introspectable — Cloudflare answers every anonymous POST with an HTML 403, so no tool names or input schemas are recorded anywhere in this repository.

## Callable today, without a contract

- [Yardi Systems Status API](https://status.yardi.com/api): public, unauthenticated, 8 GET endpoints. 134 components in 16 product groups; seven of those groups carry an explicit `Canada` component (Voyager7s, Voyager8, Breeze, Elevate, Investor Portal, Resident Screening, Yardi EHR Interfaces). Canadian incidents and maintenance windows are named explicitly.

## What does not exist

No public developer portal (developer./developers./api./docs. do not resolve on yardi.ca or yardi.com). No OpenAPI, WSDL, OData $metadata or GraphQL published by Yardi. No webhooks, no events, no AsyncAPI. No official SDKs, CLI or Postman collection. No RESO certification — the full RESO directory contains zero Yardi, Point2 or RentCafe entries, which is expected: Canadian listings move through CREA's DDF and REALTOR.ca. No security.txt, no vulnerability disclosure policy and no bug bounty anywhere on the estate.
